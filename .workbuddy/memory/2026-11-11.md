## MCP HTTP 传输改造（按 design/mcp/HTTP_TRANSPORT_PLAN.md 执行完毕）

**服务端（P1）**
- `mcp/http/serve.ts`：`allowedHosts`/`allowedOrigins`/状态文件改为在 `Bun.serve()` 成功后用 `bunServer.port` 计算，支持 `port: 0`；新增 `usageFlushMs` 注入点；`Content-Length` > 4 MiB 直接 413。Bun 1.3.9 端口占用错误 `code === "EADDRINUSE"`（已实测）。
- `mcp/http/cli.ts` 新增：`serve` 子命令、`--port/--settings/--parent-pid`、退出码 3/4/1、SIGINT/SIGTERM/SIGBREAK、父进程看门狗（2s 轮询 `process.kill(pid,0)`）。
- `mcp/main.ts`：`argv[0] === "serve"` 分流，其余走 stdio。
- 测试：`mcp/tests/http.test.ts` 18 个用例 + 进程级看门狗；`mcp/tests/expected-tools.ts` 抽出 76 工具清单供 coverage-matrix 与 http 测试共用。

**关键坑（重要）**：Bun 1.3.9 同一进程内多个 `Bun.serve` 存活时，所有请求都由**第一个**存活实例的 `fetch` 处理；测试必须保证同一时刻只有一个存活服务（`withServer()` 包裹并 stop）。生产环境无影响。

**GUI（P2）**
- `src-tauri/src/commands/mcp_server.rs`：设置模型（`#[serde(flatten)] extra` 保未知字段）、0600 原子写、`cmk_`+32B base64url 令牌、10 个命令、`TcpStream` 直接解析 `/healthz`。
- 进程托管：`McpServerProcess { child, owned, starting, last_error }`；`setup` 起线程 autostart；`.build().run()` 在 `RunEvent::Exit` 调 `stop_owned_server` 只停自己启动的进程。
- `mcp_token_update` 的 `family` 语义：**省略=不改，空串=改回动态发现**（Tauri 对缺失键直接 `visit_none`，不能用 `Option<Option<String>>`）。
- 前端：`McpSettingsPage` 重写；新增 `McpServerStatusCard`/`McpTokenTable`/`McpTokenDialog`/`McpHttpSnippets`/`labels.ts`/`httpSnippets.ts`；删除 `McpConfigSnippets.tsx`（其 `buildMcpCliArgs` 测试迁到 `httpSnippets.test.ts`）；审计日志加「客户端」列。
